# Decision log

Every non-trivial choice, with the alternatives, the reason and the evidence (which data part it came from).
"Item-level" means computed from news text only, with no click data. Entries D01 to D13 were back-filled on
2026-10-26 from the earlier phases; the dates are when each decision was made.

| ID | Date | Decision | Alternatives | Reason | Evidence |
|---|---|---|---|---|---|
| D01 | 2026-10-12 | Score title and abstract separately; combine with TITLE_WEIGHT 0.3 / ABSTRACT_WEIGHT 0.6, normalised to 1/3 : 2/3; empty abstract -> title only | Keep the single combined-text score | 76% of items were dominantly neutral on combined text; supervisor approved the redesign. The weights were set by the student/supervisor, not tuned | None from clicks (design decision). Combined baseline kept as `news_emotion.parquet` |
| D02 | 2026-10-12 | Combine the raw 28 sigmoid scores first, then derive every feature | Derive features per field, then combine | Noisy-OR and normalisation do not commute with a weighted mean; one combined score vector keeps every feature consistent | Mathematical, no data |
| D03 | 2026-10-12 | Abstract max_length 256 (titles 128) | 128 for both | 0.48% of abstracts are truncated at 128 tokens, 0.055% at 256; length-sorted batching makes 256 cheap | Item-level token counts (`results/tables/token_lengths.json`) |
| D04 | 2026-10-12 | Abstract batch size 64 | 32 | Smoke test: batch 32 x 256 tokens peaked at 0.73 of 6 GB GPU; batch size does not change scores | Hardware measurement |
| D05 | 2026-10-12 | go_dist_* uniform only at an exact zero sum; add go_emotion_mass | Uniform below a threshold | Avoid an arbitrary threshold; mass lets later congruence weight or filter noisy distributions | 69.8% of items have mass < 0.1 (item-level) |
| D06 | 2026-10-15 | Lexicon fields without hits: renormalise the 1/3 : 2/3 weights over fields with hits; none -> 0 and has_hits = 0 | Treat a field without hits as all-zero | A share is undefined without hits; zero would mean "no emotion", not "unknown" | Item-level: 28.3% of titles have no EmoLex emotion hit |
| D07 | 2026-10-15 | Simple regex tokens, unigrams, no negation, no lemmatisation; topic words such as "police" (fear, trust) and "trump" (surprise) are NOT filtered | Stop lists, negation handling | Filtering would be an undocumented, data-driven change; artefacts are reported instead | `results/tables/lexicon_top_words.csv` |
| D08 | 2026-10-15 | Add go_pct_* (percentile rank across all items) and go_title_* / go_abs_* variants; keep go_dist_* | Use raw scores only | GoEmotions labels have different floors on neutral text, so raw scores and go_dist_* mostly reflect label baselines at low mass | Item-level score distributions (Phase 2). Chosen before any click analysis; Phase 5 later showed percentiles carry more click signal (fit), which was not used to choose them |
| D09 | 2026-10-16 | Primary test = one-sample t-test on per-impression clicked-minus-unclicked differences, Holm; Wilcoxon kept as a robustness column only | Wilcoxon signed-rank (original spec); permutation p-values | The null distribution of a mean difference (1-2 clicks vs ~35 non-clicks, skewed features) is asymmetric, so Wilcoxon is biased | fit, labels shuffled within impressions: Wilcoxon 93/101 false positives, t-test 0/101 |
| D10 | 2026-10-16 | Add a user-level check (mean difference per user, t-test across users, Holm; same sign required) | Impression level only | Impressions of the same user are not independent | fit: 85/101 features significant at both levels |
| D11 | 2026-10-16 | Congruence profile from the `history` column only (decay 0.9, newest weight 1, last 50, cold start = corpus mean), plus a generic corpus-mean control | Profiles from impression clicks | Impression clicks would leak the target; MIND history is one fixed list per user from before the log period | fit: cold start 1.95% of impressions |
| D12 | 2026-10-26 | Rename `*_excess` to `*_personal` (= personal_congruence = measure(user) - measure(corpus mean)) | Keep "excess" | Same term in code, tables and report | Naming only |
| D13 | 2026-10-26 | Add a shuffled-user control (`*_otheruser`, `*_userspecific` = raw - other user). ADDED AFTER SEEING RESULTS, as a stricter robustness check; the pre-declared `*_personal` is kept unchanged | Report `*_personal` only | Histories are past clicks, so every profile is shifted from the corpus mean towards "typically clicked news"; `*_personal` can then be positive without personalisation. A random other user's profile keeps that shared shift but breaks the user link | fit: cong_pct_cos_otheruser dz 0.089 (not 0), personal 0.242, user-specific 0.136; all at both levels |
| D14 | 2026-10-26 | -KL on go_pct_* kept, marked "exploratory, not pre-declared"; included in the same Holm family | Drop it | It was computed in the same run; dropping it after seeing results would hide a test. Including it makes Holm slightly more conservative | fit |
